Implementation Plan

Transform the search tab from a dead-empty screen into a useful discovery hub. Three changes, ordered by impact.

1

Empty State: Recent Notes + Upcoming Todos

When the search input is empty, show two sections:

  • Upcoming & Overdue — reuses the existing getUrgentTodos() query, showing overdue items in red, today in orange, and future in neutral.
  • Recent Notes — new query: SELECT * FROM notes ORDER BY updated_at DESC LIMIT 10. Shows note title, category color dot, and relative timestamp.
  • Recent Searches — stored in AsyncStorage (simple string[], max 5). Tapping fills the search input.

DB cost: One new query + one new hook. No schema changes.

2

Filter Chips: Category + Type

Add a horizontal scrollable filter bar below the search input:

  • Type toggles: All / Notes / Todos — filter the FTS results client-side by type field.
  • Category chips: Loaded from existing useCategories(). Each chip shows the category color dot + name. Selecting one filters results to that category.
  • Chips are single-select per group (type + category), visually toggled with the primary color fill.

DB cost: Extend the FTS query with optional WHERE category_id = ?. Type filter is client-side.

3

Richer Results: Snippets + Metadata

Upgrade result display from bare title to contextual cards:

  • Body snippet: Use SQLite snippet() function on the FTS table to extract a ~60-char context window around the match. Show below the title, with the matched term in bold/highlight.
  • Category badge: Color dot + category name on each result row (already in data, just not rendered).
  • Relative date: Show "Updated 2h ago" / "Overdue" / "Tomorrow" using the existing formatRelativeDate() helper.
  • Result count: "3 results" label above the list.

DB cost: Update FTS SELECT to use snippet(notes_fts, 1, '<mark>', '</mark>', '…', 40). Add updated_at to search result interface.
